## Исправление Windows build scripts
- Исправлена проверка Python runtime: наличие интерпретатора подтверждается специальным выводом реально запущенного Python-процесса нужной версии и разрядности, а не только кодом возврата `py`. Отсутствующий runtime больше не выбирается ошибочно.

## 0.5.0-alpha — улучшение анализа и профилей, в разработке

- Версионная проверка приведена к семантике BUTR: одиночная версия — минимальное требование; `*` в `ApplicationVersion` расширяет нижнюю границу, а не задаёт строгий префиксный диапазон; `ApplicationVersionRange` (`min - max`) и NuGet-интервалы проверяются с учётом границ. Учитывается порядок каналов Alpha/Beta/EarlyAccess/Release/Development.
- Совпадение требования BUTR при отличающейся строке версии отображается как `Info` с 0 баллов риска; фактическая версия ниже минимума или вне диапазона остаётся `Medium`. Это различает семантику BUTR и возможное предупреждение Vanilla Launcher.
- Добавлено чтение Vortex load-order JSON формата BUTR: `isSelected` — состояние включения, `isDisabled` — блокировка переключения, `index` — позиция только для аудита. Текущий порядок Vortex не управляет собственной сортировкой BCI.
- Автоопределение профиля Vortex работает только при наличии свежего дополнительного снимка полного состояния, из которого однозначно извлекается активный профиль. Тип профиля соответствует селектору BUTR: только `bannerlord_multiplayer === true` означает Multiplayer, иначе профиль Singleplayer по умолчанию. Если файлы Vortex существуют, но активный профиль не подтверждён, BCI не переключается молча на Launcher; доступен ручной выбор JSON. Файлы BUTR на этапе 0.5.0 искались в корне игры; в 0.5.1 поиск расширен на `%APPDATA%\Vortex\mountandblade2bannerlord\mods`, указанный в фактической persistence-реализации расширения.
- Для подтверждённого Singleplayer-профиля сетевые/серверные модули исключаются из графа, если профиль явно не включает их. Multiplayer/Server state не смешивается с Singleplayer.
- Интерфейс, HTML и TXT используют три состояния проверки текущего порядка: неизвестно, 0 нарушений или фактическое число нарушений.
- XML-пути используют один наиболее устойчивый ключевой атрибут в приоритете `id`, `skill_id`, `key`, `slot`, `name`, `type`; остальные атрибуты сравниваются как значения. Позиционные индексы остаются для анонимных списков.
- Направленное обязательное отношение `DependedModules` классифицирует пересечение как кандидат штатного переопределения дополнения (Info/0); третий модуль считается только кандидатом patch, если он зависит от обоих модов и редактирует общий спорный XML-объект. Роль patch автоматически не подтверждается.
- Добавлен постоянный SQLite-кеш SHA-256 по нормализованному пути, размеру и `mtime_ns`; чекбокс полной перепроверки обходит кеш и пересчитывает хеши. Кеш отдельный и не изменяет историю сканов/модели.
- Удалена неиспользуемая функция `_module_file_fingerprint` и дублирующий блок заметки отсутствующего порядка.
- Добавлены `tests/test_bci_p1_p2.py` и регрессионные сценарии. Полный набор `pytest`: **68/68 успешно** в Python 3.13.5.
- Не проверены: запуск Tkinter на Windows, реальное обнаружение активного профиля Vortex на машине пользователя, Windows PyInstaller/Inno Setup, игровые A/B/A-сценарии и большие реальные сборки. ZIP не содержит `.git`; GitHub не изменялся.

- Проверка совпадающих путей ресурсов сначала сравнивает размеры файлов: разные размеры сразу доказывают различие содержимого и позволяют не читать большие ресурсы ради SHA-256; для файлов одинакового размера полный SHA-256 сохраняется.
- В отчёт добавлены отдельные показатели хеширования ресурсов, объёма прочитанных данных, путей с разным размером и файлов, пропущенных по доказанному различию размеров.
- В доказательствах Resource Override сохраняются размеры файлов и способ сравнения; неполное чтение больше не описывается как подтверждённое совпадение. Оригинальный регистр путей ресурсов сохраняется при открытии файлов.

- Дальнейшие оптимизации производительности приостановлены до появления подтверждённой проблемы на реальных больших сборках. Приоритет — точность, полнота и проверяемость анализа.
