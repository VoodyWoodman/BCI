# BCI 0.3.1-alpha — отчёт о QA

Дата: 24.11.2026

## Автоматические проверки в среде разработки

- Python syntax compilation (`py_compile`) для приложения и основных модулей: успешно.
- Unit tests: **21/21 успешно**.
- `git diff --check`: успешно.
- Для XML-оптимизации выполнено 100 случайных дифференциальных сравнений старой и новой логики; результаты совпали во всех 100 случаях.
- Локальная среда разработчика: Linux, Python 3.13.5. Windows-сборка на этой машине не запускалась.

## Синтетическая проверка XML-сравнения

На 100 искусственных модулях с примерно 1 000 XML-объектов на модуль время этапа сравнения в текущей среде:

| Сценарий | Старая логика | Новая логика |
|---|---:|---:|
| Нет общих объектов | 0,274 с | 0,074 с |
| Редкие пересечения | 0,311 с | 0,082 с |
| Все объекты общие | 4,51 с | 2,67 с |

Это лабораторные результаты алгоритмического теста, а не гарантия для реальной сборки Bannerlord.

## Синтетическая проверка размера ресурсов

Для двух файлов приблизительно по 92 МиБ, отличающихся по размеру на один байт, проверка совпадающего пути сократилась с 181–245 мс до менее 0,1 мс. В новой реализации файлы не читались ради SHA-256, так как разные размеры уже доказывают различие содержимого. Для одинакового размера SHA-256 остаётся обязательным.

Во всех отчётах: 14 230 файлов обнаружено; 5 350 файлов / 253,7 МБ захешировано при инвентаризации; 4 120 кандидатов ресурсов; 16 совпадающих путей; 14 путей с различными размерами; четыре файла одинакового размера прошли SHA-256, около 0,3 МБ.

**Граница измерения:** время `scan_modules` не включает Baseline, ML inference, SQLite persistence и HTML/JSON export. Это не полное end-to-end время операции.

В этих отчётах попарное сравнение сторонних XML не получило реальной нагрузки: сторонних XML-записей, общих XML-объектов и сравнений было ноль. XML-оптимизация проверена синтетическими и дифференциальными тестами, но не подтверждена реальными XML-пересечениями в пользовательской сборке.

## Что ещё не проверено

- Реальные сборки из 50 и 100 модов.
- Полное end-to-end время вместе со всеми пост-этапами приложения.
- Пиковое потребление RAM полного сканирования.
- Чистая установка, upgrade и uninstall Windows на отдельной машине.
- Работа определения активного профиля BEM на разных конфигурациях.
- Реальные сторонние XML-пересечения в модовом наборе пользователя.
- Независимая Windows CI сборка установщика.

## Следующий приоритет

Качество анализа: проверить BEM и активные модули, собрать реальные примеры сторонних XML-пересечений, оценивать ложные срабатывания и пропуски, расширять golden/regression cases. Дальнейшая оптимизация производительности приостановлена до появления измеренной проблемы на реальной крупной сборке.
